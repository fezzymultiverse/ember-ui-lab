# Ember V1.9.51 API-platform audit

The provider layer was audited across authentication, model discovery, request construction, streaming, fallback, cooldowns, Free Mode, key bookkeeping, tool calls, and provider status UI.

Three concrete reliability issues were fixed. First, a provider returning HTML or another non-JSON error body could cause the error parser itself to throw because it dereferenced a null parsed value; the router now preserves the provider error and continues its normal fallback path. Second, OpenAI-compatible SSE responses whose final `data:` line is not followed by a newline could lose the last answer fragment; the stream parser now flushes the buffered final line. Third, the model picker could reuse a cached model list indefinitely through `modelsOf()`; it now refreshes lists after the same 12-hour TTL used by normal routing.

The API contracts were checked against the current official documentation. Groq and Mistral still use OpenAI-compatible `/chat/completions` endpoints with streaming, tools, and JSON modes. Gemini still requires the `x-goog-api-key` header and exposes `generateContent`; model selection remains live-list based so changing Gemini model names do not require another hard-coded release. Sources: [Groq API reference](https://console.groq.com/docs/api-reference), [Mistral Chat endpoint](https://docs.mistral.ai/api/endpoint/chat), [Gemini API reference](https://ai.google.dev/api), and [Gemini models](https://ai.google.dev/gemini-api/docs/models).

The new API audit test passes all three checks. Provider fallback, streaming, tool calling, JavaScript syntax, the existing Thinking stability suite, plus-menu checks, and the focused legacy provider tests pass. The tool-calling browser test passes when run with the project’s separate Playwright dependency. Real credentials were not present in the supplied source package, so the ZIP does not claim to have performed live calls against the user’s accounts; the app’s existing Settings > Keys > Check all control remains the place to verify each key on the user’s device.
